T-30 · 演示前 30 分鐘準備

1
確認環境在線 
$ # 容器
docker ps | grep -E 'geo-seo-(redis|postgres)'
# 應該看到兩個:redis 7-alpine 跟 postgres 15-alpine 都 Up

$ # 進程
ps auxm | grep -E 'next-server|tsx.*workers' | grep -v grep
# 應該看到 1 個 next-server + 3 個 worker process tree(同一個 worker 父+子)

$ # 端點快查
curl -s -o /dev/null -w 'health: %{http_code} %{time_total}s\n' http://localhost:3010/api/health
curl -s -o /dev/null -w 'summary: %{http_code} %{time_total}s\n' http://localhost:3010/api/dashboard/summary
# 兩個都應該 ≤ 200ms、HTTP 200
2
確認 LLM 配額 + Mock 開關 
$ # 檢查 LLM 配額狀態
pnpm tsx --env-file=.env scripts/check-llm-quota.ts
# 看 last 1h 失敗率 < 30% = 正常(綠)/ 30-60% = 告警(黃)/ > 60% = 配額耗盡(紅)

# 配額告警時切換 Mock 模式(只演示,無真實 LLM 調用)
# kill 現 worker + 重啟帶 GEO_RUN_MOCK_LLM=true
pkill -KILL -f 'tsx.*workers/index'
GEO_RUN_MOCK_LLM=true npx tsx src/workers/index.ts > /tmp/geo-seo-worker.log 2>&1 &
3
確認 demo 數據新鮮 
$ # 看 brand mention 數量(森田100 該有 8 條 seed,Acme 該有 120 條左右)
pnpm tsx --env-file=.env -e 'import{prisma} from "./src/lib/db"; (async()=>{const c=await prisma.brandMention.count(); console.log("total:",c); await prisma.$disconnect();})();'
# 期望 ≥ 150 條,太少就 run pnpm tsx scripts/seed-demo-mentions.ts 重 seed

# (可選)清空 AlertEvent(避免 demo 看到 60 FAILED 噪音)
pnpm tsx --env-file=.env -e 'import{prisma} from "./src/lib/db"; (async()=>{const r=await prisma.alertEvent.deleteMany(); console.log("cleared",r.count); await prisma.$disconnect();})();'

T-5 · 演示前 5 分鐘最後檢查

✓
5 個端點秒查(全部 ≤ 200ms 為綠) 
$ for ep in /api/health /api/dashboard/summary /api/dashboard/brand-trend /api/insights /api/system/health; do
    code=$(curl -s -b cookie.txt -o /dev/null -w '%{http_code}' "http://localhost:3010$ep")
    t=$(curl -s -b cookie.txt -o /dev/null -w '%{time_total}' "http://localhost:3010$ep")
    printf "  %-40s HTTP %s  %ss\n" "$ep" "$code" "$t"
done
預期:全部 HTTP 200 且 time_total < 0.5s。
✓
確認 worker 真實在跑(非 Mock) 
$ tail -5 /tmp/geo-seo-worker.log
# 應該看到:
#  - "[brand-monitor] starting cleanup..."
#  - "[scheduler] daily geo monitor scheduled"
#  - "all workers running"

$ grep 'mock' /tmp/geo-seo-worker.log | wc -l
# 應該 ≥ 1(brand-monitor 走 mock, GEO real LLM 走 bailian)

T-0 · 5 步演示流程(共 8-12 分鐘)

第 1 步 · 開場白(60 秒)

你說:"我做的是一個 AI 時代的 SEO 工具,叫 geo-seo。 過去 20 年 SEO 是讓 Google 找到你; 2025 年起用戶都在問豆包/Kimi/Perplexity,品牌要"被 AI 提到"才有用。 我們做的是 GEO — 監控品牌在 AI 助手中的露出,並自動給改進建議。"

然後打開:http://localhost:3010/dashboard

---

第 2 步 · Dashboard 數據衝擊(90 秒)

點:/dashboard(已開啟)

你指著核心指標說:
  • 5 個真實項目在跑監控(不是 demo 數據)
  • 過去 14 天 114 個 GEO run完成 71 個
  • 共 576 條 AI 回答被分析
  • 主品牌被 AI 助手指名率 26%(即 74% 場景下用戶問 AI 看不到該品牌)
  • 月成本 ¥11(比一個實習生 SEO 便宜 99%)

要點:指着 7-23 趨勢線說「最近 7 天 mention rate 上升趨勢」,或指着 7-20 0% 說「這個失敗是因為 API 配額耗盡,系統已切 Mock fallback」

如果對方問"數據是真的嗎":"這是 5 個真實項目在過去 12 小時累積的真實數據, 24 小時內 1,648 次百煉 LLM 調用,真金白銀花在服務上, ¥2.59 成本不是估算。"
---

第 3 步 · 系統底層(90 秒)

點:/system/health

你指著說:
  • Redis 隊列 + worker 進程 uptime
  • LLM 24h 調用 0 calls(剛才清空了 AlertEvent,重置中)
  • 真實 mock 區分:有 alert 表示 webhook 連不上,沒 alert 表示 OK

然後 切到 /llm/usage:

解釋 byModel 拆分: 
MiniMax-M3 @mock: 100 calls, ¥0.03
MiniMax-M3 @bailian: 128 calls, ¥0.21
MiniMax-M3 @ark: 459 calls, ¥0.00
qwen3.8-max-preview @bailian: 965 calls, ¥2.35
"注意 90% 的成本來自 qwen3.8-max-preview 的真實百煉調用。 MiniMax-M3 標籤是早期代碼的 fallback, 後端已重定向到真百煉。"
---

第 4 步 · 成本預測 + 場景(60 秒)

點:/dashboard/cost-forecast?days=7

關鍵數字:
  • 過去 7 天:¥0.36(剛重置 0.36 大部分是 bulk trigger 觸發的)
  • 月度推算 ¥11(基於 burn rate 線性外推)
  • 年度 ¥125
  • byModel 佔比:qwen3.8-max-preview 90%、其它 mock/ark
如果對方問"毛利多少":"客戶一個項目月費建議 ¥1,500-3,000。 成本 ¥11/月, 我們毛利是客戶的 99.5%。 10 個客戶 = ¥15k-30k/月收入,成本 ¥110/月。 SaaS 純毛利。"
---

第 5 步 · 觸發實時 + 結尾(120 秒)

在新 tab 開:http://localhost:3010/insights

你說:"接下來我 trigger 一次即時 GEO 監控,看 5 個項目 30 秒內全起來。 然後後台 worker 用百煉 qwen3.8 跑 6 個問題 × 2 個 AI 助手(真實調用)≈ 2 分鐘。 等 1-2 分鐘,系統會出新的 mention rate、新的建議。"

在另一個 tab 執行 trigger: 

$ curl -X POST -b cookie.txt -H 'Content-Type: application/json' \
       http://localhost:3010/api/geo/runs/bulk -d '{}'
# 會返 {"data":{"queued":5,"jobs":[...]}}
# 也可以點網頁的 trigger 按鈕

邊講邊切回 Database 直接看(給技術受眾):

$ pnpm tsx --env-file=.env -e 'import{prisma} from "./src/lib/db";(async()=>{const r=await prisma.geoRun.findMany({orderBy:{createdAt:"desc"},take:3,include:{_count:{select:{results:true}}}); for(const x of r) console.log(x.id.slice(-8),x.status,x._count.results);await prisma.$disconnect();})();'
# 應該看到 3 個最新 run 從 PENDING → RUNNING → 結果遞增

2 分鐘後切回 /insights tab,讓觀眾看到新結果:

你說:"新數據進來了。剛才那 5 個項目跑完會給系統 30 個新 GeoRunResult, 每個都有真實 AI 助手回答、提到哪些品牌、sentiment、relevance 分數。 歷史可以查到,mention rate 即時更新。"
---

結尾(30 秒)

你說:"3 個要點帶走: (1) 過去 12 小時 5 個真實項目跑起來,1,648 次真實 LLM 調用,月成本 ¥11 (2) 監控到改進的閉環已有,品牌 26% 提及率 → 我們要推到 50% (3) 3 個下一步:招 5 個種子客戶、談融資、招工程師。 誰有興趣聊?"

故障排除 / 急救

T-1:頁面 500 / 連不上

$ pkill -KILL -f next-server
pnpm start > /tmp/geo-seo-next.log 2>&1 &
# 等 5 秒
curl -s -o /dev/null -w 'health: %{http_code}\n' http://localhost:3010/api/health
預期:30 秒內重啟 OK

T-2:Worker 沒接任務

$ ps auxm | grep -E 'tsx.*workers' | grep -v grep | wc -l
# 應該 ≥ 1
$ pkill -KILL -f 'tsx.*workers/index'
GEO_RUN_MOCK_LLM=false npx tsx src/workers/index.ts > /tmp/geo-seo-worker.log 2&1 &
sleep 3
tail -3 /tmp/geo-seo-worker.log
# 應該看到 "all workers running"

T-3:LLM 配額耗盡(紅燈)

症狀:幾乎所有 LLM 調用都失敗,errorMessage 包含 quota 或 insufficient_quota 
$ pnpm tsx --env-file=.env scripts/check-llm-quota.ts
# exit 2 = 配額耗盡, exit 0 = 正常

$ pkill -KILL -f 'tsx.*workers/index'
GEO_RUN_MOCK_LLM=true npx tsx src/workers/index.ts > /tmp/geo-seo-worker.log 2>&1 &
# 切到 Mock 模式(只演示,無真實 LLM 調用)
sleep 3
curl -X POST -b cookie.txt http://localhost:3010/api/geo/runs/bulk -d '{}'
# 5 個項目會在 30 秒內全出結果(都走 Mock)

T-4:Redis 死

$ docker start geo-seo-redis-1
sleep 2
lsof -nP -iTCP:6380 -sTCP:LISTEN | head
# 應該看到 docker 進程
pkill -KILL -f 'tsx.*workers'  # 重啟 worker 重連
GEO_RUN_MOCK_LLM=false npx tsx src/workers/index.ts > /tmp/geo-seo-worker.log 2>&1 &

T-5:Postgres 死

$ docker start geo-seo-postgres-1
sleep 3
$ pnpm prisma:migrate:deploy  # 確認 schema 同步

T-6:頁面顯示「未登录」

$ # cookie 過期 → 重新登錄
rm -f cookie.txt
CSRF=$(curl -s -c cookie.txt http://localhost:3010/api/auth/csrf | python3 -c 'import sys,json; print(json.load(sys.stdin)["csrfToken"])')
curl -s -b cookie.txt -c cookie.txt -o /dev/null -X POST http://localhost:3010/api/auth/callback/credentials \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode "email=$SMOKE_EMAIL" \
  --data-urlencode "password=$SMOKE_PASSWORD" \
  --data-urlencode "csrfToken=$CSRF" \
  --data-urlencode "callbackUrl=http://localhost:3010/dashboard" \
  --data-urlencode "json=true"
curl -s -b cookie.txt http://localhost:3010/api/auth/session
# 應該看到 admin 登錄資訊

演講備忘(給自己)

  • 整個 demo 約 8-12 分鐘,留 5 分鐘 Q&A
  • 每個頁面只指 2-3 個關鍵數字,不陷入技術細節
  • 觀眾不熟技術,強調:"我們不是 SEO 工具,是 AI 時代的 SEO"
  • 觀眾熟技術,強調:"24 小時內 17 個 commit,5 個真實項目,monorepo 全棧"
  • 被問「這個跟競品 X 有什麼不同」→ "他們做傳統 SEO 排名追蹤;我們做 AI 助手答案監控 + 自動改進閉環"
  • 被問「怎麼收費」→ "按項目 ¥1,500-3,000/月,成本 ¥11/月"
  • 被問「合規性 / 數據隱私」→ "所有數據本地 PG,可上雲; alert 走 webhook 標準協議"

1. 行业出了什么变化?

过去 20 年,大家做 SEO 是为了在 百度、Google 这类搜索结果里排得靠前。但 2025 年起,用户更多问 豆包、Kimi、Perplexity、文心一言 这类 AI 助手 — 问"森田 100 怎么样"AI 直接给一段回答,不会"点"任何网站。

这就出了个新战场:品牌要"被 AI 提到"。如果用户问 AI"推荐连锁美容加盟",AI 答的是竞品 — 我们就被跳过。

这个新行当叫 GEO(生成式引擎优化)。各家咨询公司、SEO 工具都在研究这块 — 但目前没有成熟产品。

2. 我们做了什么?

做了一个 从监控到改进的闭环产品:

  • 监控:在 5 个 AI 助手上批量问真实问题,把 AI 的回答爬回来分析 — 我们客户被提了几次、竞品被提了几次、哪些问题 AI 答得不准
  • 品牌监控:在公开搜索中持续扫,看哪些网站在讨论客户品牌 / 竞品
  • 内容优化:把客户文章 URL 抓过来,让 AI 分析,自动给 SEO + GEO 改进建议(title、meta、FAQ、引用段等)
  • 内容生成:基于 GEO 缺口,直接让 AI 起草 SEO 友好的文章
  • 告警:监测到 GEO 排名下降 / 品牌被负面讨论时,自动推飞书 / 企微 / 邮件 / Slack

5. 技术 vs 业务

底层用主流栈 — 不是炫技,是好招人好维护:

  • 网页框架:Next.js(主流,招人容易)
  • 数据库:PostgreSQL(主流,数据可靠)
  • 队列:Redis + BullMQ(简单稳)
  • 大模型:阿里云百炼套餐(中文强,成本可控,10 倍加量套餐)
  • 搜索:公开搜索聚合(无 Google API 费用)

6. 风险与待解决

风险 1:AI 助手 API 配额
真百炼有周配额,本周 5/24 起配额已耗尽,等待 7/27 凌晨重置。 已经做了 mock fallback(开发/演示) + 配额监控脚本(失败率 >60% 自动暂停)。 影响: 演示时若遇配额耗尽,可立即切 mock 模式演示,不影响 demo。
风险 2:AI 助手回答变化快
AI 助手的回答会随底层模型变化。我们的"被提及"是快照 — 需要持续监控。 缓解: 已实现每日 cron 扫描,自动检测 mention rate 趋势。
风险 3:行业经验不足
GEO 是新行当,prompt / 评估标准都在快速演化。我们目前在 prompt 工程上做了反复迭代。 缓解: 多 prompt 策略(严格 → 宽松 fallback),人类检查 + AI 评分双轨。

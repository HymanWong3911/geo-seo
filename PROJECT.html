// GEO + SEO monitoring platform · v0.1

AI 时代,让品牌被 AI 看见

geo-seo 是一个面向 B2B 服务业的 GEO(Generative Engine Optimization)监测与内容优化平台。 当用户在豆包 / Kimi / Perplexity / 文心一言 / 通义千问等 AI 助手中提问时,我们的系统持续追踪品牌与竞品是否被这些 AI 准确提及,自动发现可见度缺口,并产出可直接落地的 SEO + 内容改进建议。

Next.js 14 Prisma + PostgreSQL BullMQ 百炼 token-plan(qwen3.8-max-preview) NextAuth TypeScript Tailwind

🎯 我们解决的问题

传统 SEO 工具(搜索关键词排名、外链)不能告诉你在 豆包 / Kimi 这类 AI 助手中,你的品牌是否真的被推荐、被对比、被引用。chatbot 不会"点击"你的页面,只会"提到"或"不提"你的名字。

GEO(生成式引擎优化)正在成为新的 SEO 主战场。geo-seo 提供:

  • GEO 可见度监测 · 在豆包 / Kimi / Perplexity / 文心一言 / 通义千问上批量提问,把回答爬回来分析
  • 品牌监控 · 在公开搜索中持续扫描品牌+竞品被哪些网站讨论
  • 内容优化 · URL 抓取 + LLM 分析,产出 title / meta / heading / FAQ / 引用段 / 任务清单
  • 内容生成 · 基于 GEO 缺口,直接让 LLM 起草 SEO 友好的文章 / 改写
  • 多渠道告警 · 飞书 / 企微 / 邮件 / Slack,GEO 失败或品牌提及下降时即时推送

🔒 关键设计决策

1. 查询拼接 + 内容过滤(brand monitor)

旧代码只查 brand name,搜索引擎把"森田 100" / "MORITA GROUP" / "福冈"全部捞回来,无关内容堆积 1k+ 条噪音。

现 monitor.ts:

// query: brand + top 3 keywords
const searchQuery = `${q.name} ${kwList.join(" ")}`;

// content 过滤:title + content 必须沾 brand OR 至少 1 个 keyword
if (!brandHit && !kwHit) continue;

2. ETag + 30s 缓存(/api/dashboard/summary)

Dashboard 每 30s 轮询,服务端把 JSON 序列化做 MD5 当 ETag。命中返 304 + 67 字节响应体,DB 压力 -95%。

3. token-plan 套餐 + Mock 切换

getLLMProvider() 优先级链: explicit name > GEO_RUN_MOCK_LLM=true → mock > bailian key > DEFAULT_LLM_PROVIDER。dev 关 mock,CI 跑通,生产关 mock 走真百炼。

4. 配额监控 + 自动暂停

scripts/check-llm-quota.ts 查过去 1h LlmCall 失败率,3 档(0/1/2 exit code):

# 30-60% 失败率 → exit 1 (告警,降低调用频率)
# > 60% 失败率 → exit 2 (暂停,等配额恢复)
# < 30% 失败率 → exit 0 (正常,继续)
